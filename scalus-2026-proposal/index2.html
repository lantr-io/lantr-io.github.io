What Scalus is

A shared application platform for building, verifying, launching, and scaling serious Cardano applications, with one stack for smart contracts, chain access, runtime operations, and native L2 scaling.

Why now

Protocol upgrades, critical integrations, DeFi liquidity, and VC capital are aligning. The next bottleneck is no longer core infrastructure. It is application delivery.

Already used by / integrating with

Hydrozoa · Bifrost · Sugar Rush · Vela

MeshJS SDK · Cardano Client Lib · Evolution SDK · 3 years of continuous delivery

What you are voting for

A shared platform that helps Cardano teams build apps, verify them, launch them with sovereign chain access, and scale them with native L2 support.

Solutions Building On Scalus

Existing demand, not hypothetical demand

Scalus is already being used in ecosystem work. These examples show the kind of serious applications and infrastructure this proposal is meant to accelerate.

In plain English

What Scalus is meant to deliver

Not another disconnected tool. One coherent stack that carries a Cardano application from prototype to production.

01

Build apps

Smart contracts, transaction logic, blueprints, and developer tooling in one environment for serious Cardano applications.

02

Verify correctness

In-memory emulator, configurable devnet, enterprise testing, and formal verification workflows for higher-assurance systems.

03

Launch sovereignly

Runtime infrastructure and application-owned L1 chain access so production apps depend less on stitched-together external services.

04

Scale with L2

Native Hydrozoa / Gummiworm integration on the same platform when applications need more throughput than L1 alone can provide.

The Core Problem

The bottleneck is assembly

Teams trying to ship non-trivial Cardano applications still have to assemble too many moving parts themselves. That slows delivery, raises operating complexity, and pushes teams toward shortcuts.

Design it well

Correct UTxO modeling, composable contracts, and product architecture for non-trivial applications.

Verify it is correct

Debugging, formal verification, enterprise-grade testing, and security work before production.

Launch it

Reliable chain access, application runtime, deployment flows, and production operations without fragile shortcuts.

Scale it

Throughput and operating costs beyond what L1 alone can offer, without leaving the same platform.

Why vote yes

This is growth infrastructure for Cardano

The proposal funds a reusable open-source platform intended to reduce time-to-production for multiple serious applications, not just one vendor product.

01 · Existing platform

Not greenfield

Scalus already has three years of delivery behind it, with active partner adoption, ecosystem integrations, and open-source traction.

02 · Ecosystem-wide value

Reusable public goods

Shared application infrastructure reduces repeated assembly work across many teams instead of solving only one application in isolation.

03 · Sovereign operations

Mission-critical by design

Embedded or standalone L1 chain access gives bridges, bots, oracles, and protocols a stronger path to resilience and self-sovereignty.

04 · Adoption path

Three target use cases

New Cardano applications, mission-critical systems, and applications with native L2 scaling all use the same platform journey.

05 · Treasury safeguards

Governable delivery
