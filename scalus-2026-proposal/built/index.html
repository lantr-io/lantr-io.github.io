Delivery

What gets built

Twelve months. Four milestones from Q3 2026 to Q2 2027. Each milestone ships independently usable capability and is reviewed by an Independent Technical Assurer before release of the next disbursement.

Roadmap

Four milestones, twelve months

Milestone-based delivery between July 2026 and June 2027. The progression follows the application lifecycle: chain access first, scaling second, verification third, production hardening last.

M1

Applications with sovereign chain access

Q3 2026 · Jul – Sep 2026
  • Reactive runtime and embedded L1 node
  • Persistence and UTxO indexing
  • Operational observability stack
  • Independent Technical Assurer review
Builders can ship Bootstrap apps, batchers, indexers, reactive applications running against their own embedded chain access.
M2

Applications with native L2 scaling

Q4 2026 · Oct – Dec 2026
  • Native Hydrozoa / Gummiworm integration
  • JVM interop: Spring Boot, Ktor
  • Browser-native experiments
  • Independent Technical Assurer review
Builders can ship Scaled DeFi apps anchored to L1, Java/Kotlin integrations into existing backends, throughput-sensitive applications.
M3

Formal verification & advanced devnet

Q1 2027 · Jan – Mar 2027
  • Blaster (Lean) formal verification integration
  • Custom L2 ledgers
  • Dijkstra early access
  • Mainnet forking devnet
Builders can ship Higher-assurance protocols, formally verified critical paths, custom L2 applications, mainnet-forking integration tests.
M4

Censorship-resistant operations

Q2 2027 · Apr – Jun 2027
  • Production hardening of L1 node, relay-capable
  • Mempool watcher and event-sourced submission
  • DeFi connectors and Docker packaging
  • Security audits and final assurance
Builders can ship Production-grade DeFi, MEV-aware systems, standalone chain-access services, regulated-environment deployments.

By June 2027, Scalus delivers a unified application platform for more self-sovereign, production-grade, and scalable Cardano applications. Each milestone's deliverables are open-source and reusable beyond Lantr.

Use cases

What teams will build with this

Three primary use cases shape the platform: new applications moving from idea to first production, mission-critical systems needing sovereign chain access, and applications scaling through native L2.

New Cardano applications

Teams moving from idea to first working application on Cardano with one coherent stack — scaffolding, starter kits, smart contract blueprints, in-memory emulator, configurable devnet, and testnet launch.

Examples: lending protocol, auction, AMM starter kit

Mission-critical applications & protocols

Production-grade DeFi, bridges, oracles, and operator systems that need rigorous testing, formal verification, sovereign chain access, and operational resilience.

Examples: Hydrozoa / Gummiworm L2, Binocular Bitcoin oracle, DeFi Kernel SDK, market-making and arbitrage bots

Applications with native L2 scaling

Applications that need higher throughput, lower operational overhead, or custom business logic through native Hydrozoa / Gummiworm integration.

Examples: Sugar Rush DEX (CLOB), prediction market, perpetuals platform

Scalus supports the full product journey from first prototype to production-grade, scalable systems — without switching tools, languages, or environments along the way.

Adoption targets

Measurable outcomes at handover

Four concrete adoption targets agreed in advance. The Independent Technical Assurer reviews these against actual delivery before the final disbursement is released.

≥ 1 Demonstrated application per use case (3 use cases) by end of delivery period.
≥ 5 Product teams building with Scalus, excluding Lantr.
≥ 2 Production-like deployments using Scalus-owned chain access.
≥ 2 Ecosystem integrations extended or deepened during the delivery window.
